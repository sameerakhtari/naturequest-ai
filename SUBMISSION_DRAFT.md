## What I Built

**What if an AI app measured success by how quickly it convinced you to close your laptop?**

That question became **NatureQuest AI**: an offline-first outdoor exploration companion designed to move people *away* from endless scrolling and toward real-world curiosity.

Rather than being another app to spend hours inside, NatureQuest creates a short adventure that you can actually complete outside. You choose **where** you're exploring (a park, backyard, city, trail, or coastline), **how** you're feeling (curious, calm, active, or creative), and **how much time** you have. Gemma 3 then creates three simple discovery activities. The final instruction is the important part: **put your phone away and go notice something**.

Afterward, you can upload a photograph of something that caught your eye. An open-weight vision model, running through Ollama on a machine you control, helps you describe visible details, suggests what to look for next, and openly acknowledges uncertainty. Your observations and completed adventures go into a private field journal stored in the browser.

Three principles guided the build:

- **Keep the screen time short.** Three focused tasks replace an endless feed of suggestions.
- **Make curiosity safer than false certainty.** The model is prompted to describe observations, acknowledge limits, and avoid risky species-identification or foraging advice.
- **Keep the outdoors available without AI.** When Ollama cannot be reached, a curated mission generator still works. The interface makes clear when content is curated rather than generated by Gemma.

The audience is anyone with a little free time, a nearby outdoor space, and a desire to notice more of the world around them.

## How I Built It

**1. The model is the creative engine, not the entire product.**

NatureQuest uses Google's **Gemma 3 4B** open-weight multimodal model served by Ollama. The backend sends a small, structured prompt describing the chosen environment, mood, and duration to the local chat endpoint. Gemma must return a JSON object with a title, short introduction, three activities, and a closing message. FastAPI validates the result before it reaches the UI.

If inference is down or the response is invalid, NatureQuest falls back to a set of safe, curated activities and visibly labels the result as an **offline field guide**. This is a deliberate product choice: exploring outside should never depend on the uptime of an AI service.

**2. Nature observation is multimodal, private by default, and uncertainty-aware.**

The observation feature accepts a JPEG, PNG or WebP photograph. Before sending it to Ollama, the FastAPI/Pillow pipeline enforces upload and image-size limits, removes EXIF metadata during conversion, and creates an in-memory JPEG resized to at most 1024 × 1024 pixels. It does not write the uploaded image to application storage.

The model is asked to describe evidence visible in the photo, suggest a follow-up observation, disclose uncertainty, and encourage safe, non-disruptive exploration. NatureQuest is a companion, **not** a professional species or food-safety identifier.

**3. The journal belongs to the user.**

Photos, personal notes, and completed adventures are stored in the browser's **IndexedDB**. The journal can be exported to JSON. No login, location permission, remote database, or analytics service is required. A service worker caches the static application shell for repeat visits. Without access to Ollama, AI analysis cannot run, but the saved journal and curated missions remain useful.

**4. I kept the deployment deliberately small.**

The frontend uses no JavaScript framework, package registry, or bundler. FastAPI serves the app directly. A Python virtual environment or Docker Compose is enough to run the project. The repository includes automated API tests with mocked inference, but those tests are **not** a substitute for checking real Gemma responses in the running application.

## Why Does Open Innovation Matter?

An application like this could be built around a closed cloud vision API. But doing that would create the very dependencies I wanted to avoid: uploading potentially private outdoor photographs to an external AI provider, needing an API key, and depending on a paid service whenever someone wants to explore.

With **Gemma 3 running locally through Ollama**, inference can stay between the web app's backend and a model endpoint under the operator's control. There is no automatic hosted-model fallback. Someone can inspect the prompts, change the model, adjust the JSON validation, or develop more responsible observation experiences without waiting for a proprietary API feature.

There are honest tradeoffs. A local multimodal model needs storage and compute resources; on some hardware it will be slower than a cloud service, and it may still make mistakes. That is why NatureQuest emphasizes **careful observations**, displays uncertainty, and has a non-AI fallback rather than claiming perfect identification.

Open innovation made more than a technical stack possible here. It made a different relationship with technology practical: **an AI assistant that gives you a reason to leave it behind**.
